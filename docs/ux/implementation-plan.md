> **Superseded (2026-11-20):** Zach chose Lookbook with Strand motion ([redesign-options.md](redesign-options.md)),
> applied on branch `claude/lookbook-redesign-232f2e`. The Chair-side visual PRs below won't be built. Items that
> aren't about the look (session-kept quiz answers, one shared hair vocabulary) are still open ideas.

How to move `web/` from the inherited "Ledger" styling (pokemans) to [design-direction.md](design-direction.md) in
small PRs, client flow first. Each PR is one module's files where possible, keeps tests green
(`cd web && npm test && npm run lint && npm run build`), and changes no behaviour except where it says so.
PRs marked **backend** change an API: run `./gradlew test -Dopenapi.update=true`, then `npm run api:types` in `web/`.

Order is by user impact: clients first (they decide whether the pilot works), then stylists (supply), then the admin
(one person, desktop). Updated 2026-11-20 for the auto-publish decision: matches publish in seconds, clients can see
all stylists, and the admin monitors instead of approving.

Notes:

- **Coordination with `claude/lookmate-auto-publish`.** That branch changes publishing (automatic, with the review
  switch), adds the directory endpoint and the admin log's data. PRs 7, 8b and 11 build on it and touch the same files
  (`MatchStatusPage.tsx`, `FindPage.tsx`, `MatchQueuePage.tsx`, `MatchReviewPage.tsx`, `App.tsx`), so they start after
  it merges; restyle on top of its behaviour rather than racing it. Route and field names in this plan are proposals:
  use whatever that branch shipped.
- **Parallel work.** 1 must merge first. After that, the client track (2→4→5→7→8, plus 6) and the stylist track
  (3→9→10) can run in parallel sessions; both touch `index.css` only through PR 1, and 3 is the one shared file
  (`hair.ts`), so merge 3 before starting 4 or 9. 7a and 8a are backend-only and can start any time.
- **Tests.** Most component tests query by role and label; PR 3 and 4 change visible labels, so those tests change in the
  same PR. Add a token contrast test in PR 1 (parse `index.css`, check the documented pairs ≥ 4.5:1 and borders ≥ 3:1) so a
  later colour tweak can't silently fail AA.
- **Order within the client track:** 2 → 4 → 5 → 7 → 8 → 8b, with 6 any time after 2. The instant-results transition
  (7) is the highest-impact client change once auto-publish is live, because it replaces a day's wait with seconds.
